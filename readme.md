## PostgreSQL OrderHistory ID deployment

After provisioning the CAP PostgreSQL schema, and before starting the service
or testing Cancel in DEV or QA, apply the versioned standalone database artifact:

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db-deployer/migrations/001-orderhistory-id.sql
```

Use the target environment's database connection and schema search path, with
the table/sequence owner's credentials. Supply credentials securely; do not
commit them. Run during a maintenance window with application writers stopped.
The migration locks OrderHistory against writes, preserves all records, creates
and owns its ID sequence, and sets the ID default. It advances the next ID beyond
both existing records and the sequence's allocated values, without rewinding it
on subsequent runs. An empty history starts at ID 1.

Apply this artifact again after any schema rebuild that recreates OrderHistory.
The CDS integer key is generated by this PostgreSQL default, not by copying the
Failed Orders technical ID. This does not change connector 1.0.2 or XSUAA identity.

Regression checks (run the SQL check only against a disposable test database):

```sh
node --test --test-concurrency=1 test/acquire-lock.test.js
psql "$TEST_DATABASE_URL" -v ON_ERROR_STOP=1 -f db-deployer/test/orderhistory-id.sql
```
